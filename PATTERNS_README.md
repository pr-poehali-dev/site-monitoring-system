# 📊 Анализ паттернов упоминания документов

Инструменты для анализа и улучшения логики парсинга связей между документами в системе мониторинга.

---

## 🎯 Цель проекта

Найти все возможные формулировки упоминания предыдущих версий документов (типа "утратившим силу", "в редакции постановлений", "внести изменения" и т.п.) для улучшения автоматического поиска связей.

**Результат:** +15-20% больше найденных связей, +10-15% точность определения.

## 🔍 Основные находки

### Проблема 1: Пропущенные варианты глаголов

**Текущий код:**
```python
r'утратившим\s+силу'  # Только одна форма
```

**Решение:**
```python
r'утратившим\s+силу'   # было
r'утрачивает\s+силу'   # добавить
r'утрачивают\s+силу'   # добавить
r'утратил[оа]?\s+силу' # добавить
```

### Проблема 2: Обратный порядок не всегда работает

**Пример из документа:**
```
"от 15.05.2024 года №456"
```

**Текущий паттерн:**
```python
r'от\s+(\d{2}\.\d{2}\.\d{4})\s+года?\s+(?:№|N|#)\s*(\d+)'
```

**Проблема:** Не учитывает короткий год (YY) и латинскую N.

**Решение:** См. `pattern_improvements_recommendations.md`

### Проблема 3: Множественные ссылки в скобках

**Пример:**
```
"(в редакции постановлений от 01.01.2020 №1, от 02.02.2021 №2, от 03.03.2022 №3)"
```

**Текущее поведение:** Находит только первую ссылку.

**Решение:** Специальная обработка блоков в скобках с увеличенным контекстным окном.

### Проблема 4: Ложные срабатывания

**Примеры:**
```
"телефон 8-800-123-45-67"  ❌
"счет №123 от 01.01.2023"  ❌
"ИНН 1234567890"           ❌
```

**Решение:** Фильтрация по ключевым словам (телефон, счет, банк, ИНН и т.п.)

## 🔧 Технические детали

### Структура базы данных

```sql
-- Таблица документов
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    title TEXT,
    document_number VARCHAR(50),
    document_date DATE,
    related_to INTEGER REFERENCES documents(id),  -- Ссылка на предыдущую версию
    related_count INTEGER DEFAULT 0,              -- Количество ссылающихся документов
    file_cdn_url TEXT,
    is_phantom BOOLEAN DEFAULT FALSE,
    ...
);

-- Таблица логов поиска связей
CREATE TABLE link_finding_logs (
    id SERIAL PRIMARY KEY,
    document_id INTEGER REFERENCES documents(id),
    found_references JSONB,      -- Найденные ссылки
    matched_documents JSONB,     -- Совпавшие документы в БД
    log_data JSONB,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Алгоритм парсинга

```
1. Скачать файл (DOCX/PDF)
2. Извлечь текст (первые 20-30 параграфов)
3. Найти ключевые фразы ("утратившим силу", "внести изменения" и т.п.)
4. В контексте ключевых фраз искать номера и даты
5. Валидировать найденные ссылки
6. Искать соответствующие документы в БД
7. Создать связи (related_to)
```

### Производительность

- Анализ 1 документа: 2-5 секунд
- Анализ 100 документов: 3-8 минут
- Полная переиндексация 1000 документов: 30-60 минут
