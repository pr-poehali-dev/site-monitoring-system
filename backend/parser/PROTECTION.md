# 🛡️ Система защиты от зависаний парсера

Многоуровневая защита для надёжной работы в cron без ручного вмешательства.

## Проблема

Cloud Functions имеют жёсткий таймаут (30 сек). Если функция не успевает завершиться:
- Статус остаётся `running` 
- База данных не обновляется
- Следующий запуск не знает что делать
- Требуется ручной сброс

## Решение: 4 уровня защиты

### 1. ⏱️ Таймаут-защита (20 сек вместо 30)

**Где:** `parse_single_year()`, `parse_docs()`

```python
max_execution_time = 20  # Запас 10 сек до hard timeout
```

**Как работает:**
- Проверка времени перед обработкой каждой страницы
- При достижении 20 сек → сохранение статуса `partial` + текущей страницы
- Следующий запуск продолжит с этой страницы

**Логи:**
```
⏱ ПАРСИНГ ПРИОСТАНОВЛЕН ПО ВРЕМЕНИ
Обработано годов: 3
Время: 20148мс
Причина: защита от timeout Cloud Function
```

---

### 2. 🔄 Автоматический сброс застрявших задач

**Где:** `continue_parsing()` (первый шаг), `parse_single_year()` (при старте)

```python
STUCK_TASK_TIMEOUT = 300  # 5 минут
```

**Как работает:**
- При каждом вызове `continue_parsing()` проверяются задачи со статусом `running`
- Если `updated_at` старше 5 минут → автоматический сброс в `pending`
- Аналогично в `parse_single_year()` при старте работы с годом

**Логи:**
```
⚠️ АВТО-СБРОС: Задача programmy 2020 застряла на 12 мин (страница 5)
Причина: статус "running" без обновлений более 5 минут
Действие: сброс в "pending" для повторной обработки
```

---

### 3. 💾 Непрерывное сохранение прогресса

**Где:** После каждой обработанной страницы

```python
cursor.execute(
    f"UPDATE parsing_state SET page = %s, updated_at = CURRENT_TIMESTAMP ...",
    (page, section, year)
)
conn.commit()
```

**Как работает:**
- После каждой страницы: обновление `page` и `updated_at`
- При достижении лимита страниц/документов → статус `partial`
- При отсутствии кнопки "Далее" → статус `completed`

**Результат:**
- Если функция упадёт на странице 10 → следующий запуск начнёт со страницы 10
- Никакие данные не теряются

---

### 4. 🚨 Обработка всех ошибок

**Где:** `parse_single_year()` (try/except)

```python
try:
    # Парсинг страниц
except Exception as e:
    if new_retry < MAX_RETRY:
        status = 'retry'  # Попробуем ещё раз
    else:
        status = 'failed'  # Исчерпаны попытки
```

**Как работает:**
- Любая ошибка → сохранение в `last_error`
- До 3 попыток → статус `retry`
- После 3 попыток → статус `failed`

**Логи:**
```
⚠️ Ошибка, будет повтор 1/3: Connection timeout
```

---

## Статусы задач

| Статус | Описание | Действие при следующем запуске |
|--------|----------|-------------------------------|
| `pending` | Задача создана, не начата | Начать парсинг с page 1 |
| `running` | Задача выполняется | Если > 5 мин → сброс в `pending` |
| `partial` | Частично завершена | Продолжить с сохранённой страницы |
| `completed` | Полностью завершена | Пропустить |
| `retry` | Ошибка, будет повтор | Повторить попытку |
| `failed` | Исчерпаны попытки | Требуется ручное вмешательство |

## Как это работает в cron

### Сценарий 1: Нормальная работа
```
09:00 - cron запускает continue_parsing()
09:00 - Обработка programmy 2024: 5 страниц за 15 сек → completed
09:00 - Обработка programmy 2023: 8 страниц за 18 сек → partial (page=9)
09:01 - cron запускает continue_parsing()
09:01 - Продолжение programmy 2023 с page=9: 3 страницы за 8 сек → completed
```

### Сценарий 2: Timeout функции
```
09:00 - cron запускает continue_parsing()
09:00 - Обработка postanovleniya 2025: 15 страниц
09:00:20 - Достигнут лимит 20 сек → сохранение partial, page=16
09:00:30 - Cloud Function hard timeout (функция убита)
09:01 - cron запускает continue_parsing()
09:01 - Продолжение postanovleniya 2025 с page=16 → completed
```

### Сценарий 3: Crash функции
```
09:00 - cron запускает continue_parsing()
09:00:05 - Начало обработки programmy 2020 (status=running, page=1)
09:00:08 - CRASH (OutOfMemory / bug в коде)
09:00:08 - Статус остаётся running, page=1
09:01 - cron запускает continue_parsing()
09:01 - Обнаружена задача running > 5 мин → АВТО-СБРОС в pending
09:01 - Повторная обработка programmy 2020 с page=1
```

## Мониторинг

Все действия защиты логируются в `parsing_logs`:

```sql
SELECT section, level, message, created_at 
FROM parsing_logs 
WHERE message LIKE '%АВТО-СБРОС%' 
OR message LIKE '%ЗАВИСАНИЕ%'
ORDER BY created_at DESC;
```

## Настройка констант

В `backend/parser/index.py`:

```python
MAX_RETRY = 3                    # Попыток при ошибке
MAX_DOCS_PER_RUN = 200           # Документов за итерацию
MAX_PAGES_PER_RUN = 50           # Страниц за итерацию
MAX_ITERATIONS_PER_YEAR = 20     # Итераций на 1 год (защита от циклов)
STUCK_TASK_TIMEOUT = 300         # Секунд до признания зависшей (5 мин)
```

**Рекомендации для cron:**
- Запуск каждую минуту: `* * * * *`
- Или каждые 30 секунд через systemd timer
- Защита сама подберёт незавершённые задачи

## Тестирование защиты

### Тест 1: Имитация timeout
```python
# В parse_single_year() временно установить:
max_execution_time = 5  # 5 секунд вместо 20
```
Ожидаемый результат: статус `partial`, продолжение в следующем запуске

### Тест 2: Имитация crash
```python
# В parse_single_year() добавить:
if page == 3:
    raise Exception("Test crash")
```
Ожидаемый результат: статус `retry`, повтор в следующем запуске

### Тест 3: Имитация зависания
```sql
UPDATE parsing_state 
SET status = 'running', updated_at = NOW() - INTERVAL '10 minutes'
WHERE section = 'programmy' AND year = 2020;
```
Запустить `continue_parsing()` → ожидаемый результат: АВТО-СБРОС в `pending`

## Итого

✅ **Парсер устойчив к:**
- Timeout Cloud Function (30 сек)
- Случайным ошибкам (сеть, парсинг)
- Сбоям платформы
- Перезапускам сервера

✅ **Не требует:**
- Ручного сброса задач
- Мониторинга состояния
- Вмешательства при ошибках

✅ **Гарантирует:**
- Парсинг завершится всегда (или статус `failed` с описанием)
- Данные не теряются (прогресс сохраняется)
- Автоматическое восстановление после любых сбоев
