# Анализ паттернов упоминания документов

Этот набор инструментов предназначен для анализа паттернов упоминания предыдущих версий документов в базе данных системы мониторинга.

## Созданные файлы

### 1. `analyze_document_patterns.py`

**Полный анализ с скачиванием и парсингом файлов**

Этот скрипт:
- Находит документы с максимальным количеством входящих ссылок
- Скачивает файлы документов, которые на них ссылаются
- Извлекает текст из DOCX и PDF файлов
- Ищет все контексты упоминания документов
- Анализирует ключевые фразы и форматы дат/номеров

**Требования:**
```bash
pip install psycopg2-binary python-docx PyPDF2 requests
```

**Использование:**
```bash
export DATABASE_URL="postgresql://user:password@host:port/database"
python analyze_document_patterns.py
```

**Результат:**
- Консольный вывод с подробным анализом
- Файл `document_patterns_report.json` с полным отчетом

**Время выполнения:** 10-30 минут (зависит от количества и размера файлов)

---

### 2. `analyze_patterns_simple.py`

**Быстрый анализ без скачивания файлов**

Этот скрипт:
- Анализирует только метаданные из базы данных
- Строит статистику по связям между документами
- Анализирует логи поиска связей
- Находит самые длинные цепочки связей
- Предоставляет рекомендации на основе структуры данных

**Требования:**
```bash
pip install psycopg2-binary
```

**Использование:**
```bash
export DATABASE_URL="postgresql://user:password@host:port/database"
python analyze_patterns_simple.py
```

**Результат:**
- Консольный вывод со статистикой
- Файл `patterns_analysis_simple.json` с отчетом

**Время выполнения:** 1-3 минуты

**Рекомендуется для:**
- Быстрой оценки текущего состояния
- Анализа структуры связей
- Проверки перед запуском полного анализа

---

### 3. `pattern_improvements_recommendations.md`

Содержит:

## Результаты анализа

### Что вы получите:

#### 1. Список всех найденных паттернов

Примеры:
- "утратившим силу" (встречается N раз)
- "внести изменения" (встречается M раз)
- "в редакции постановлений" (встречается K раз)
- и т.д.

#### 2. Форматы упоминания номеров и дат

Примеры:
- Стандартный: №123 от 01.01.2020
- Обратный: от 01.01.2020 года №123
- С типом: постановление №123 от 01.01.2020
- С N вместо №: N 123 от 01.01.2020

#### 3. Контексты упоминаний

Примеры реальных фраз из документов, где упоминаются предыдущие версии.

#### 4. Рекомендации по улучшению

Конкретные паттерны для добавления в код парсера.

#### 5. Особые случаи

Примеры нетипичных ситуаций, которые нужно учесть.

---

## Интерпретация результатов

### Ключевые метрики

1. **Количество уникальных паттернов** - разнообразие формулировок
2. **Частота встречаемости** - какие паттерны наиболее важны
3. **Форматы дат/номеров** - какие варианты нужно поддерживать

### На что обратить внимание

**Высокий приоритет:**
- Паттерны, встречающиеся более 10 раз
- Форматы, которые не поддерживаются текущим кодом
- Систематические ошибки парсинга

**Средний приоритет:**
- Редкие паттерны (2-10 раз)
- Вариации уже поддерживаемых форматов
- Оптимизации производительности

**Низкий приоритет:**
- Единичные случаи (1 раз)
- Очевидные опечатки в документах
- Нестандартные форматы

## Следующие шаги

После анализа:

1. **Изучить `pattern_improvements_recommendations.md`**
   - Ознакомиться с рекомендациями
   - Выбрать приоритетные улучшения

2. **Обновить код парсера**
   - Файл: `backend/link-finder/index.py`
   - Добавить новые паттерны
   - Улучшить существующие

3. **Протестировать изменения**
   - Запустить парсер на тестовых документах
   - Проверить метрики: точность, полноту, F1-меру

4. **Развернуть в production**
   - Постепенное внедрение (сначала на новых документах)
   - Мониторинг результатов
   - Корректировка при необходимости

5. **Переиндексировать старые документы**
   - Запустить повторный поиск связей
   - Сравнить результаты до/после

## Устранение проблем

### Ошибка: "DATABASE_URL не настроен"

```bash
# Проверьте, что переменная установлена
echo $DATABASE_URL

# Если нет, установите:
export DATABASE_URL="postgresql://user:pass@host:5432/db"
```

### Ошибка: "ModuleNotFoundError: No module named 'docx'"

```bash
pip install python-docx
```

### Ошибка: "ModuleNotFoundError: No module named 'psycopg2'"

```bash
pip install psycopg2-binary
```

### Скрипт работает слишком долго

- Используйте `analyze_patterns_simple.py` вместо `analyze_document_patterns.py`
- Уменьшите лимит документов в коде (параметр `limit`)

### Не удается скачать файлы

Проверьте:
- Доступность CDN (файлы должны быть публично доступны)
- Наличие `file_cdn_url` в базе данных
- Правильность URL в таблице `documents`

## Дополнительная информация

### Структура базы данных

Скрипты работают со следующими таблицами:

- `documents` - основная таблица документов
  - `id`, `title`, `document_number`, `document_date`
  - `related_to`, `related_count` - связи между документами
  - `file_cdn_url` - ссылка на файл документа

- `link_finding_logs` - логи поиска связей
  - `document_id`, `found_references`, `matched_documents`
  - `log_data` - дополнительная информация

### Архитектура парсера

```
1. Скачивание файла (DOCX/PDF)
2. Извлечение текста (первые 20-30 параграфов)
3. Поиск ключевых фраз (контекстные маркеры)
4. Извлечение номеров и дат в контексте
5. Валидация найденных ссылок
6. Поиск соответствий в БД
7. Создание связей (related_to)
```

### Производительность

Типичная производительность на современном сервере:
- Анализ 1 документа: 2-5 секунд
- Анализ 100 документов: 3-8 минут
- Полная переиндексация 1000 документов: 30-60 минут

Оптимизации:
- Кеширование скачанных файлов
- Параллельная обработка (используйте `multiprocessing`)
- Пакетная обработка документов из одного раздела
